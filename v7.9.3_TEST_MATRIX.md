# v7.9.3 Test Matrix

| Gate | Test | Required result |
|---|---|---|
| G1 | Detect Debit/Credit headers on PJ, PJ Non-Vat, CDJ, SJ, CRJ, GJ | Explicit mapping or HOLD |
| G1 | Resolve account from explicit account field / TIN mapping | No silent fallback to zero |
| G2 | Extract January–December journal rows | Deterministic population |
| G2 | Re-run extraction without changing source data | Identical totals |
| G3 | Total posted Debit vs Credit | Difference <= 0.01 |
| G4 | Reconcile mapped activity to GL COA | No unexplained mapped activity |
| G4 | Unmapped journal accounts | Listed separately in `GL_AUDIT` |
| G5 | January opening balance | Explicitly supplied and reproducible |
| G5 | February–December carry-forward | Prior ending balance + current movement |
| G5 | 46-account matrix | 552 account-month results available for validation |
| G6 | GL write | Must not execute when validation is HOLD |
| G7 | Graphify | Consumes GL output only; never selects accounting fields |

## Required negative tests

1. Remove/rename a required header: result must be `HOLD`, not zero totals.
2. Introduce an unmapped account: validation must fail and identify unmapped activity.
3. Change one journal debit without its balancing credit: validation must fail.
4. Change one journal date: only the affected month/year should change.
5. Supply a non-zero opening balance: ending balance must shift by exactly that opening amount.
6. Re-run with unchanged inputs: all account-month totals must remain unchanged.

## Important interpretation

The existing v7.9.2 evidence records a `Cost of Revenue` GJ amount of `1,139` as unmapped while known-source debit and credit totals were both `256,145.75`. Therefore **balanced != fully mapped**. v7.9.3 treats the unmapped state as a validation HOLD rather than silently accepting the GL as complete.

# v8.0 Final Review — Workbook-Based GL Hardening

## Review target

Workbook: `Global-Smile_2026-v7.9.xlsm`

The workbook was inspected directly before changing the v8.0 source design.

## Critical v7.9.3 findings

1. The generic v7.9.3 engine treated all six journals as independent posting sources. In this workbook, PJ/PJ Non-Vat feed CDJ and SJ feeds CRJ, so posting all six would double-count feeder activity.
2. The journal sheets do not use one universal row-level Date/Account schema. Periods are encoded differently by source:
   - CDJ: month marker in column C and entry log in column X.
   - CRJ: transaction date is embedded in the Entry Logs column.
   - GJ: month marker persists in column B.
   - PJ/PJ Non-Vat/SJ are feeder journals, not direct GL posting sources.
3. GJ contains valid posting accounts that are not present in the 46-account GL list.

## v8.0 design correction

Authoritative posting sources are now **CDJ + CRJ + GJ**.

The v8.0 engine:
- uses exact workbook columns rather than generic header guessing;
- uses source-specific period extraction;
- does not post feeder journals twice;
- normalizes documented GJ spelling/label aliases;
- treats ambiguous/unmapped accounts as HOLD;
- builds a separate `GL_V8_CALC` 46×12 calculation matrix;
- never overwrites the existing GL while validation is HOLD.

**Repository:** `D:\citrixlabph\globalsmile` (branch `main`, HEAD `8097c55`)

**Status:** read-only investigation complete. No sheet, formula, VBA module or workbook was modified; nothing committed.

---

## 1. Executive summary

1. **The three questioned sheets (`GL_V8_CALC`, `COA_MAP`, `GL_AUDIT`) are not load-bearing.** The GL calculation reads none of them, and none of them contains a single formula. They are acceptance/QA scaffolding added by the build scripts, not by a requirement of the automation.
2. **The contracted GL path is simple and unchanged since v7.0:** `PJ / PJ Non-Vat → CDJ`, `SJ → CRJ`, then `CDJ + CRJ + GJ → ScanGL → GL`. The GL sheet still uses the original 46-account × 12-month block layout (stride 13, first row 13, columns B–I). Complexity was added *around* GL, never *into* it.
3. **The calculation itself is proven correct.** On `Global-Smile_2026-v8.3.3.xlsm` an independent Python reconciliation (no VBA, no shared code) reproduces the GL exactly: Debit = Credit = 258,671.00, **0 of 46 accounts differ, 0 of 552 month cells differ, 0 unmapped, 0 invalid**.
4. **The GL in v8.4 is a stale snapshot**, not a calculation: 258,671.00 stored against 9,400,982.03 of posted debits and 9,389,792.06 of posted credits in the shipped journals. It matches the certified 2026-10-02 run and the workbook's own `V8.3_FINAL_REVIEW` sheet, which records 258,671 / PASS.
5. **It is stale because the scan gate deliberately refuses to write** (`modGLScanEngine.bas:289` — PASS requires `|Dr−Cr| ≤ 0.01 AND unmapped ≤ 0.01 AND invalid = 0`; on v8.4 all three fail). The gate is correct; the data is not.
6. **Three data/code causes, fully quantified** (§9): 559 of 562 CRJ rows carry no date and are dropped (₱3,447,227.77); sundry labels fail an exact-string match (₱930,534.90 recoverable by normalisation + ₱754,485.03 needing an accounting decision); 232 duplicate CDJ rows (₱1,904,187.06).
7. **The shipped VBA project does not compile as delivered** (§10.1): `modGLGate` calls two functions that were removed with `modGLAggregation`, and `modEngine` contains self-referencing `Legacy_*` procedures under `Option Explicit`. Static evidence only — no macro was executed in this investigation.

**Net conclusion:** no sheet needs to be added, deleted, split or renamed; no COA duplication; no workbook redesign. The fix is three small code changes plus one operator data decision (§13).

### 2.2 Method

- **VBA dependency analysis:** full-text search of the 26 exported modules in `gate2_work/vba_baseline/` for every sheet name, function call and constant.
- **Independent validation:** `recon_gl.py` — a from-scratch re-implementation of the posting rules transcribed from the workbook's own column headers, deliberately sharing no code with VBA. It aggregates posted journals to `(account, month)` and compares against the stored GL cell by cell.

- **Sundry analysis:** `sundry_map.py` — every CDJ column-S label resolved against the 46 GL titles by exact match, punctuation-insensitive match, then fuzzy match.

All three scripts are reproducible and can be committed on request.

## 6. As-built GL data flow

```
PJ / PJ Non-Vat ── modEngine.SyncPJToCDJ / SyncPJNonVatToCDJ ──► CDJ
SJ ────────────── modEngine.SyncSJToCRJ ──────────────────────► CRJ
CDJ + CRJ + GJ ──► modGLRefresh.RefreshGL / RefreshAllGL      (only entry points)
                        └──► modGLScanEngine.ScanGL(year=2026)
                                ├─ ScanCDJ  (col F cash, cols 7–18 allocations, col S sundry)
                                ├─ ScanCRJ  (col H cash, cols 9–12 credits, date from col O)
                                ├─ ScanGJ   (col E account, F debit, G credit, memo rows skipped)
                                └─ gate: PASS ⇔ |Dr−Cr| ≤ 0.01 AND unmapped ≤ 0.01 AND invalid = 0
                                        ├─ PASS ► WriteScannedGL → GL (cols G/H/I)
                                        │           WriteScannedCalc → GL_V8_CALC
                                        │           WriteScanAudit  → GL_AUDIT
                                        └─ HOLD ► "GL not overwritten" (modGLScanEngine.bas:37)
```

**GL layout (unchanged since v7.0):** 46 account blocks, stride 13, first block at row 13; per block 12 month rows; columns B–I = Date, (day), Reference, Explanation, Account Title, Debit, Credit, Ending Balance. Month row for block *b*, month *m* = `13 + b*13 + m − 1`.

**Mapping tables live in `modGLWorkbookMap.bas`:** `V8_CDJMap` (columns → account), `V8_CRJMap` (columns → account), `V8_GJMap` (10 aliases + dictionary lookup), `V8_GLAccounts()` (GL column-F dictionary, first occurrence wins), `V8_Norm` (UCase + Trim + NBSP only — see §9.3).

## 9. Root causes, quantified

### 9.1 R1 — CRJ rows have no date, so they are never posted

`ScanCRJ` requires a date from column O (`Entry Logs`):

```vba
dt = 0
If IsDate(ws.Cells(r, 15).Value2) Then dt = CDate(ws.Cells(r, 15).Value2)
If dt = 0 Then dt = EntryLogDate(SafeText(ws.Cells(r, 15).Value2))
If dt = 0 Then inv = inv + 1: GoTo NextRow      ' row dropped entirely
If year(dt) <> yr Then GoTo NextRow
m = month(dt)
```

Measured on v8.4: column O is populated on **3 of 562** invoice rows (SJ import timestamps dated August 2026); column D has **0** dates. Result: **559 rows invalid, ₱3,447,227.77 of debits and the same credits dropped**, and the 3 surviving rows are booked to August/September from an *import* timestamp rather than their true month.

**But the month information exists.** Column D is not a date column — it carries the month **TOTAL rows** of each partition, and the six of them reconcile exactly:

| CRJ partition | Rows | TOTAL row | Cash (col H) total |
|---|---|---|---:|
| January | 10 – 114 | r115 `JANUARY` | 593,273.12 |
| February | 117 – 196 | r197 `FEBRUARY` | 450,514.28 |
| March | 199 – 316 | r317 `MARCH` | 837,607.99 |
| April | 319 – 389 | r390 `APRIL` | 421,057.12 |
| May | 392 – 486 | r487 `MAY` | 548,191.71 |
| June | 489 – 581 | r582 `JUNE` | 606,743.55 |
| **Σ** | **562 rows** | | **3,457,387.77 = Σ col H** ✓ |

Each block's first data row also carries a leading month label (r117, r199, r319, r392, r489). **Zero new structure is needed** — the partitions are already in the sheet.

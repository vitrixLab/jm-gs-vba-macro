# v8.3.2 RefreshGL Fix — Review Gate

Base: `c34cc62791ec66eec590980a22493eedaf31408f` (v8.3.1 debugging)

## Scope

This PR is limited to the existing `RefreshGL` execution path. It does not redesign PJ, PJ Non-VAT, SJ, CDJ, CRJ, or GJ.

Required flow remains:

`PJ + PJ Non-VAT → CDJ`
`SJ → CRJ`
`CDJ + CRJ + GJ → GL`
`GL → 46 COAs × 12 months = 552 monthly positions`

## Changes

1. **Compile/runtime hardening**
   - Declares the existing CDJ signed accumulator explicitly under `Option Explicit`.
2. **Preserve 46 physical GL blocks**
   - `GL_V8_CALC` now iterates the 46 physical GL account blocks from the workbook rather than iterating the unique-key account dictionary.
   - This prevents a duplicate COA title from collapsing the expected 46 × 12 matrix.
3. **Merged-cell guard**
   - GL debit/credit target cells are checked before writing.
   - `GL_V8_CALC!A4:E555` is checked before clearing.
   - A layout violation fails closed instead of producing a partial GL write.
4. **Recalculation**
   - Excel calculation is explicitly requested after the GL write.
5. **Existing audit path preserved**
   - `GL_AUDIT` remains the diagnostic output for reconciliation/mapping status.

## Acceptance gate

This PR is **source-level ready for workbook runtime testing**. The repository cannot certify the embedded `.xlsm` binary until the VBA modules are compiled and `RefreshGL(2026)` is executed in desktop Excel.

Required runtime evidence:

- no VBA compile error;
- no merged-cell error 1004;
- 46 physical COA blocks;
- 12 months per block;
- exactly 552 `GL_V8_CALC` rows;
- CDJ, CRJ and GJ month propagation retained;
- no unmapped GJ Cost of Revenue activity;
- Debit/Credit reconciliation passes;
- cumulative ending balances are populated;
- `GL_AUDIT` records the result.

Known prior runtime evidence of `-1,139.00` imbalance and incomplete active account-month population is therefore treated as **not yet resolved by source review alone**; the Excel runtime gate remains mandatory.
